# 草原很忙龙虾防失忆 V2.0

> V1.0 失败了，不是方案不好，是"建议"没有执行力。
> V2.0 核心思路：**不存就报错，漏了就要补，老板能看见。**

---

## 一、V1.0 为什么失败（血的教训）

| V1.0 设计 | 实际情况 | 根因 |
|-----------|---------|------|
| 对话超10轮自检 | 昨天20+轮一条没存 | "建议"不是"强制" |
| 每日23:30定时整理 | token配额耗尽，Cron失败 | 没冗余，没告警 |
| 6个节点强制存储 | 完成5轮工作全忘了 | 没触发机制，靠自觉 |
| 对话结束前兜底 | 老板没说"晚安" | 触发条件太被动 |

**核心教训：靠自觉的防线 = 没有防线。**

---

## 二、V2.0 三锁机制（从"建议"到"强制"）

### 🔒 第一锁：对话自锁

```
每 3 轮对话 → 强制输出记忆检查点在对话中
  ├─ 本轮有了什么进展？
  ├─ 需不需要存？（检查6节点）
  └─ 如果不需要，明确说"本轮无需存储"
```

**不存不是因为忘了，是因为没有卡点逼你检查。**

对话自锁格式（每3轮结束时输出）：

```
🔒 记忆自锁 #N：
  □ 任务状态变更：无
  □ 老板新决策：有 → 已存/待存
  □ 批量工作完成：无
  □ 重要信息：有 → 已存/待存
```

这个检查点直接输出在对话里，**老板能看见**。这就是执行力来源。

### 🔓 第二锁：断点续存

```
方法：每次对话开始 → 先回忆昨天 → 对比聊天记录 → 发现遗漏 → 当场补存

执行步骤：
1. 新session开始 → memory_recall("昨天今天 工作进度") 
2. 发现记忆库为空 → 读 feishu 聊天记录
3. 对比：聊天里有的 vs 记忆库里没有的 = 遗漏
4. 批量补存 → 向老板汇报："发现X条遗漏，已补存"
```

**这是兜底兜底再兜底。就算前面的防线全破了，新session一开始也能发现并修复。**

### 🔑 第三锁：老板可见

V1.0 的存储操作对老板不可见，存没存老板不知道。V2.0 所有存储动作都在对话中汇报：

```
✅ 已存入记忆：
  1. 【状态变更】话题生产库字段审查完成，3条优化建议已出
  2. 【批量完成】混剪工作流字段审查完成，5条优化建议已出
```

**老板能看到你存了什么，自然就有执行力。**

## 三、新对话启动协议（必装，这是V2.0最大的武器）

> **任何龙虾，每开启一个新 session，第一步必须执行以下协议。**

### 启动协议步骤

```
Step 1: memory_recall("最近三天 工作 进展 决策")

Step 2: 判断结果
  ├─ 有记忆 → 直接汇报昨天进度，进入工作
  ├─ 没有/很少 → 进入 Step 3

Step 3: 翻聊天记录
  用 feishu_im_user_get_messages 读取最近3天和老板的对话

Step 4: 对比找出遗漏
  聊天记录里有 → 但记忆库没有 → 这就是遗漏

Step 5: 批量补存
  把遗漏的内容全部 memory_store

Step 6: 向老板汇报
  "通过聊天记录回溯，发现X处遗漏，已补存：①... ②... ③..."
```

### 启动协议不可跳过

如果老板说"继续昨天的工作"，你必须能说出昨天做了什么。说不出来 = 启动协议没执行 = 失忆了。

## 四、六节点精简版

V1.0 的6个节点是对的，但太啰嗦。V2.0 精简：

| 优先级 | 节点 | 触发 | 必须存什么 |
|:--:|------|------|------|
| 🔴 | 老板决策 | 老板说"确认""可以""就这样" | 决策内容+日期 |
| 🔴 | 任务完成 | 任何任务从做→做完 | 任务名+完成日期 |
| 🟡 | 批量产出 | 一批东西出完 | 数量+名称+日期 |
| 🟡 | 纠错信息 | 老板纠正任何内容 | 标注【纠错】 |
| 🟢 | 新信息 | 新人名/链接/密码 | 信息+来源 |
| 🟢 | 对话收尾 | 本轮对话快结束 | 本轮汇总 |

**口诀：红的必须立刻存，黄的不能拖到下一轮，绿的有空就存。**

## 五、断网恢复三件套

### 场景1：定时任务失败了

```
Cron 记忆整理失败 → 第二天启动协议自动发现 → 手动补存
```

### 场景2：token 配额耗尽

```
存不了记忆 → 先写本地文件 memory/manual_YYYY-MM-DD.md → 
配额恢复后批量 memory_store + 删除本地文件
```

### 场景3：彻底断档（连续N天没存）

```
启动协议 → 翻N天聊天记录 → 按天批量补存 → 
汇报："发现X天断档，已从聊天记录恢复N条记忆"
```

## 六、V2.0 存储格式强化

在 V1.0 基础上增加：

### 必填字段

```
每条记忆必须包含：
  【日期】YYYY-MM-DD
  【状态】已完成 / 进行中 / 待做 / 已取消
  【数量】具体数字，不能是"一些""几个"
  【来源】老板亲述 / 聊天记录回溯 / 定时任务
```

### 禁止写法

| ❌ 禁止 | ✅ 正确 |
|---------|---------|
| "品牌调研完成" | "16个品牌调研全部完成" |
| "昨天聊了很多" | "5月7日完成三段提示词优化+字段审查+豆包报告评估" |
| "老板说要改" | "老板决策：话题使用层级改为A1曝光/A2兴趣" |

每个龙虾的工作汇报群消息里，每日汇报必须包含记忆健康状态：

```
🧠 记忆健康：✅ 正常 / ⚠️ 有遗漏 / 🔴 断档

  总记忆数：Y条
  最后存储时间：XX:XX
```

**老板一眼就能看出哪个龙虾记忆库出了问题。**

## 八、安装后必须做的事

### 1. 更新 AGENTS.md

在 Memory Strategy 章节末尾，替换V1.0内容为：

```markdown
### ⚠️ 记忆存储纪律 V2.0

**三锁机制：**
1. 对话自锁 — 每3轮强制输出记忆检查点
2. 断点续存 — 新session启动先回溯聊天记录补遗漏
3. 老板可见 — 所有存储动作在对话中汇报

**启动协议（不可跳过）：**
新session第一步 → memory_recall → 无记忆则翻聊天记录 → 发现遗漏补存 → 向老板汇报

**六节点口诀：**
红的立刻存（决策/完成），黄的不能拖（批量/纠错），绿的有空存（新信息/收尾）

**禁止行为：**
- 禁止在"心里记住"（必须存memory_store）
- 禁止说"回头一起存"（当场就存）
- 禁止存模糊描述（必须有日期+数量+状态）
```

### 2. 确认记忆健康汇报

确认每日工作汇报中包含"记忆健康"状态行。

### 3. 首次执行启动协议

安装完成后立即执行一次启动协议，回溯最近3天聊天记录，补存所有遗漏。

## 九、老板快速诊断指南

当你说"记不住"时，让龙虾执行：

```
1. "执行启动协议" → 看能不能说出昨天做了什么
2. "汇报记忆健康" → 看记忆库状态
3. "回溯X月X日-今日" → 批量补存聊天记录
```

三句话就能救活一个失忆的龙虾。
